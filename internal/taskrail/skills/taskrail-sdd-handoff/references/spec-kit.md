# Spec Kit Handoff Reference

Spec Kit artifacts commonly include a constitution or principles, a feature
specification, clarification material, an implementation plan, task lists, and
checklists. Repositories can rename, omit, or extend these artifacts. Inspect
their content for requirements, decisions, constraints, acceptance evidence,
dependencies, ownership, and integration behavior; generated templates and
checked boxes do not establish approval or completeness.

Map a coherent, reviewed product behavior to a proposed Taskrail spec handoff.
Map notes or structured task candidates to the existing reviewable
`taskrail-import` flow. Once the Taskrail spec is approved, use
`taskrail-decompose` for approved-spec coverage and task decomposition. Record
semantic correspondences, assumptions, unresolved decisions, and information
losses instead of filling gaps from the source method's usual sequence.

Spec Kit planning tasks may reflect its own lifecycle, ownership, and execution
conventions rather than Taskrail's outcome-focused task model. Constitution scope,
clarification provenance, task completeness, synchronization, and change history
can be absent or method-specific. This handoff does not prove provenance,
approval, completeness, synchronization, change detection, round-trip fidelity,
or continuing ownership of source artifacts. It is not a universal Spec Kit
conversion.
