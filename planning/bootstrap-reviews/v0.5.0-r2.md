## Revision Decision

The skill installation flag remains explicit opt-in in both storage modes:

| Surface | Decision |
|---|---|
| `init` | No skills unless `--with-skills` is selected |
| `init --local` | No skills or assistant-directory changes unless `--with-skills` is selected |
| Implicit local bootstrap | Never installs or refreshes skills |
| `local promote` | Skills remain ignored unless `--with-skills` is selected |
| Negative flag | No `--without-skills` flag is introduced |

## Method

The review reconsidered the complete feature spec, machine companion, inherited
skill package, local-mode path model, promotion boundary, future-version
inheritance, and all v0.5 task files through four questions:

1. Consistency: can committed and local installations interpret a skill path or
   delivery rule differently?
2. Gaps: can an installed agent discover skills and retrieve managed content
   without knowing physical storage?
3. Additions: what smallest command result and task outcome closes that gap?
4. Adversarial: can broad exclusions, direct path access, implicit installation,
   or promotion expose or destroy adopter-owned content?
