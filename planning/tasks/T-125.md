# T-125 Heal duplicate Implementation Notes heading in T-110 task file

## Description

`planning/tasks/T-110-next-include-off-spec.md` (and, after this session's
transitions, `T-111-rename-not-retitle.md`) carry two consecutive
`## Implementation Notes` headings, so `task check:task-bodies`
(`TestCorpusTasksHaveOneImplementationNotesSection`) fails on `main`.

Root cause: these were written by a **stale on-PATH `taskrail` (homebrew v0.3.0)**
whose old `appendTaskNote` stamped a second heading instead of reusing the
scaffold's empty one. The current source already fixes this
(`internal/taskrail/tasks.go` `appendTaskNote`); a freshly built binary run
through `task new → start → verify → complete` yields exactly one heading. So
this is symptom cleanup of files a stale binary corrupted — there is no live CLI
bug to fix, and no code follow-up is warranted. The guard test is doing its job.

Discovered during T-111 review (go-reviewer flagged the failing full suite);
diagnosed via `task taskrail:check` (reported the on-PATH binary stale) and a
sandbox repro with a fresh build.

## Acceptance

- `planning/tasks/T-110-next-include-off-spec.md` and
  `planning/tasks/T-111-rename-not-retitle.md` each have exactly one
  `## Implementation Notes` heading, preserving the note bullets beneath.
- `task check:task-bodies` passes (no task file carries a duplicate
  `## Implementation Notes` heading).
- `taskrail validate` passes.
- Transitions for this task are run with a current binary so verify/complete do
  not re-introduce a duplicate.
